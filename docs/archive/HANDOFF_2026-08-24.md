## 5. Two environmental traps I fell into — don't repeat them

### 5.1 `playwright.config.ts`'s default `webServer` command is a trap for full-suite runs

It hardcodes fake stub values (`VITE_SUPABASE_URL=https://ci.example.supabase.co`, `VITE_API_URL=https://api.example.com/api`) copied from CI's `public_routes.spec.ts`-only job (which genuinely doesn't need a backend). If you run bare `npx playwright test`, Playwright spins its own dev server with those fake values, and **every test that does a real UI-driven signup/login will hang until timeout** — the frontend has nowhere real to send auth calls. This looks exactly like "the registration flow is broken" and is not. Always use the flags in §4. There's also an orphaned `.env.e2e` file at repo root with the *correct* values that nothing actually sources — dead documentation, don't trust it's wired to anything, but its values are correct if you want a reference.

### 5.2 Two servers on the same port produce genuinely inconsistent test results

Mid-session, Docker Desktop died from a machine-sleep event, and separately I'd manually started a debug `pnpm dev --port 8083` process that I forgot to kill. Both ended up bound to port 8083 simultaneously (macOS allows this under some socket conditions), and traffic routed unpredictably between them — including serving raw unbuilt `/src/*.tsx` from the stray dev server instead of the real built bundle. This produced *flaky, contradictory* results: the same test passed in isolation and failed in a full run. If you see that pattern, run `lsof -i :8083` (and `:8085`, `:8002`) before you suspect the app.
