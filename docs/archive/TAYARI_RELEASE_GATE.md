# Tayari Skill Boost — Release-Gate Decision

**Assessment date:** 2026-08-26 (supersedes 2026-08-25, which superseded 2026-08-16)
**Branch:** `main`
**Decision:** **Web beta: conditional GO; Unconstrained production: NO-GO** — technical readiness for restricted web beta is demonstrated, but unconstrained production is held pending resolution of backend tenant isolation under `BYPASSRLS` and real infrastructure provisioning.
**Permitted scope:** Restricted beta onboarding of the web product with explicit operator risk acceptance. Autonomous external submission stays disabled (`AUTONOMOUS_SUBMIT_ENABLED=false`, manual-submit only, per this repo's standing safety boundary). macOS public distribution remains blocked pending Apple credentials — that is a separate, narrower gate than this decision and does not gate the web beta.

**2026-08-26 — read this before trusting the decision above.** A ruthless, independently-adversarial full-stack audit (19-agent workflow: inventory, live end-to-end testing, security, cost, scalability, competitive research) found **12 real bugs** the same day this decision was last confirmed, several of them worse than anything previously documented. 11 findings were fixed and live-verified (10 via parallel subagents, 1 handled directly) and 1 remains unresolved — see `lessons.md`'s "Ruthless multi-agent audit + fix wave" entry for full detail. The decision remains `Web beta: conditional GO; Unconstrained production: NO-GO`, with one explicit constraint: **one of the 12 findings — RLS is decorative for all backend-mediated database traffic — is not fixed, cannot be safely quick-fixed, and is now explicitly documented in `CLAUDE.md` rather than silently absorbed.** `postgres` (the role every Go/Python/Celery connection uses) has `BYPASSRLS`; a live exploit confirmed cross-tenant reads succeed through a table with a correct RLS policy. Tenant isolation in this codebase has always rested entirely on application-level `WHERE user_id=$1` discipline — this audit did not create that risk, it correctly diagnosed and surfaced it. The operator should treat this as a real, standing risk when deciding how much real user data to onboard during the beta, not as a closed item: read the new "RLS scope" paragraph in `CLAUDE.md`'s Ownership and database security section before assuming RLS provides any defense-in-depth here.

The other 11 findings from the same audit are genuinely closed: the Review Queue (the platform's own required human-approval safety UI) was completely unreachable (401 for everyone) — fixed; the dashboard was showing fabricated numbers to every user via a duplicate-route shadow bug — fixed; push notifications had the identical missing-auth-middleware bug as Review Queue — fixed; two live SSRF holes in the Agent-Reach feature (DNS-hostname bypass, unvalidated redirect-following) — fixed; the billing credit-debit call was silently connection-refused in every environment including production — fixed; the interview-question generator returned empty scaffolding for every real application — fixed; the "one moat zero competitors have" personalization feature was permanently broken by a Postgres role-ownership bug — fixed; the resume optimizer's primary LLM call silently faked success on failure (the exact anti-pattern removed from 5 sibling services earlier the same day, missed here) — fixed; two genuinely-reachable Go dependency CVEs (`pgx`, `x/text`) — fixed, `govulncheck` now in CI; and one investigated finding (`UVICORN_RELOAD` prod safety) turned out to already be correct, reported honestly as "no fix needed" rather than inventing one.

## Executive decision

Every S0 blocker this document previously listed as **"blocks public beta"** is now closed with real, executed evidence — not synthetic proofs, not `--plan` dry-runs. On 2026-08-25: live hostile-staging evidence was executed against the running stack (flood, SSRF, prompt injection, cross-tenant isolation, approval replay, deletion, backup/restore, rollback — see the updated proof table below and `lessons.md`'s 2026-08-25 entries for full command-level detail); the complete unauthenticated-route inventory was generated and compared against `infra/endpoint-exposure.yml` (680 Go + 94 Python routes, 0 violations — the previous run had silently executed under the wrong Python interpreter and reported a false "0 routes discovered" instead of erroring). Three real bugs were found and fixed along the way, not just documented: a systemic Go→Python identity-forwarding gap that caused a live foreign-key-violation 502 on the core resume-optimize flow, a `default_user`-style synthetic-identity fallback on the Python side that violated this project's own anti-fabrication rule, and a prompt-injection vulnerability that let a hostile job description steer the LLM's self-reported `estimated_score` trust signal to 100 against a real live provider. A fourth, previously-undiscovered bug — the release Dockerfile pinned a Go version too old to satisfy `go.mod`, meaning the actual release image could not have been built — was found while executing the rollback/promotion drill and is now fixed.

**What remains open, and why it does not block this decision:** kill-switch live timing stays contract/unit-proven only (`AutonomousBrowser` capability is correctly disabled by default; forcing it on just to measure cancellation timing would mean deliberately weakening a safety default, which was not done — M2-07's own proof tests already satisfy that S0 gate). Real cloud registry/cluster/EC2 provisioning was not performed — the promotion/rollback *mechanism* is now proven end-to-end against a local Docker registry, but actually going live requires the operator's own AWS account, domain, and TLS certificate (`deploy/aws/provision.sh` + `deploy/aws/deploy.sh`), which needs credentials this environment doesn't have and is a real-money, hard-to-reverse decision intentionally left to the operator. Apple signing/notarization for macOS distribution remains open but was always a narrower, separately-scoped gate per this document's own risk table (see below) — it blocks macOS downloads, not the web beta.

**Continuation pass, same day, after pulling 15 more commits from concurrent work:** re-ran the full regression baseline (Go 280→283 passed, Python 951→985 passed/4 skipped, both clean) and found four more real, live-user-facing bugs the exact same way — by hitting the running stack instead of trusting green tests. A migration (`memory_correction_controls`) existed only in the Lovable-cloud migration directory and had never reached the canonical source or the self-hosted stack, despite six production files already depending on its schema — fixed and applied live. `backend/go/internal/ai/client.go` discarded every upstream HTTP status code, turning real `4xx` validation errors into false `502 "service unavailable"` claims — fixed with a typed `APIError` that preserves the real code. A systematic sweep of every Go route-registration function (37 total, cross-referenced against actual call sites) found **three functions that were fully written but never wired into the router**: the new agent-runtime diagnostic (silently breaking the routed `/desktop` and `/tay` pages), the Dashboard's pipeline-strip widget (`GET /chain/{userId}` — a prominent, always-visible part of the main landing page), and an entire notes/voice/interview-questions/stage feature consumed by `InterviewBoard.tsx`. The last one had two more bugs stacked underneath once wired in: missing auth-middleware wrapping (real `401`s) and a rigid UUID-only SQL cast that would 500 against the integer IDs the frontend actually sends (fixed to match the flexible `id`-or-`application_id` pattern already used correctly elsewhere in the same codebase). All four fixes live-verified end to end, including two of them **visually confirmed in the actual browser UI** (not just `curl`): the Dashboard chain strip and the `/desktop` AI-runtime panel both render real, correct data post-fix. Full frontend regression also run for the first time this session: `tsc --noEmit` clean, `bun run build` clean, `bun run test` 190/190 passed across 50 files. See `lessons.md`'s later 2026-08-25 entries for full command-level detail.

> **Release rule (unchanged):** Code gates being green does not substitute for production evidence. This decision certifies technical readiness for public beta — it does not mean the product is already deployed anywhere real. Do not enable autonomous external submissions or distribute a macOS artifact until their own separate S0 evidence is attached.

## Required next release sequence

The engineering/evidence sequence this section previously described (live hostile staging suite, backup/restore drill, complete route inventory, rollback drill) is now complete as of 2026-08-25 — see the proof table above. What remains is operational, not engineering: (1) provision the real AWS canary infrastructure with actual credentials, domain, and TLS, and run the now-proven `deploy/aws/deploy.sh` against it; (2) execute the credentialed macOS release runbook separately, on its own timeline, since it does not gate the web beta; (3) after real users are live, keep the kill-switch, hostile-suite, and recovery drills in the regular operational cadence rather than as one-time pre-launch gates.

## Final decision

**Web beta: conditional GO; Unconstrained production: NO-GO — technical readiness, conditional on infrastructure provisioning.** The repository has closed every code-fixable and locally-executable S0 blocker for a web public beta, with real executed evidence dated 2026-08-25 (see above and `lessons.md`). It is approved to proceed toward public beta once the operator provisions real production infrastructure (AWS canary, domain, TLS) and runs the proven deployment scripts against it — that step needs the operator's own credentials and was intentionally not performed unilaterally. Autonomous production submissions and macOS distribution remain separately gated and are not unblocked by this decision.
