Fixed this session · was live

The human-escalation gate failed open

requirements.txt pins Playwright 1.49.1; the interpreter runs 1.62.0, which removed Page.accessibility. The resulting AttributeError hit a bare except that logged a warning and continued: 

accessibility_nodes = []
  → classify_fields([])
  → questions = []
  → needs_human = False   # the all-clear

classify_fields cannot distinguish “no sensitive fields” from “nothing observed”, so a blind run produced the same result as a clean one. Sponsorship, salary, and veteran-status questions stopped reaching the human at exactly the moment the agent had lost sight of the form. Docker installs from requirements.txt, so the container and local development ran different observation paths and the defect never surfaced in CI.

Now fixed: the reader probes for both APIs, failure is logged at ERROR and recorded in observation_error, an empty node list on a reachable form counts as failure, and needs_human ORs in that error. Eight regression tests added.

Still open · your call

The pin mismatch itself is unresolved. The code now works on both versions, but requirements.txt and the installed interpreter should be reconciled — that change moves the Docker build.

03 Extension vs owned browser

Anthropic splits its two browser surfaces on a single axis: does this task require the user's identity? The pane runs a clean profile with none of your logins; the extension shares your browser's session so Claude can act as you. Everything else follows from that.

Applied to Tayari, the risk profiles turn out inverted.

Server path — Playwright / BrowserbaseExtension — MV3, today
Model reads page? Yes — raw innerText, unfenced; browser-use feeds DOM state each step No — autofill_engine.js is regex + querySelectorAll
Injection likelihood High. The page controls the text entering the model ≈ Zero. No instruction channel exists
In scope when it fires Resume PII; navigate / click / fill actions Live authenticated sessions across six ATS domains + LinkedIn
Blast radius Bounded — clean profile, owner-checked kill switch, provider terminate API Unbounded — read/write as the user across host_permissions
Guarded today Credential fills only; clicks and navigation explicitly not N/A
The rule that falls out

Never put an LLM in the extension's decision loop.

The path that can be attacked has small consequences; the path with large consequences cannot currently be attacked. The moment a model chooses what the extension clicks or types on a live page, Tayari inherits the server path's injection likelihood combined with the extension's blast radius — and every mitigation it owns sits on the wrong side of the boundary.

If the extension ever needs judgment: send structured fields to the server, get back values, apply them locally. The model issues values, never actions.

Verdict

The server-side owned browser is primary for all agentic work. The extension is primary for identity-bearing submission, and must stay LLM-free.

  • No identity needed — discovering postings, reading a JD, opening a public Greenhouse/Lever/Ashby form, filling name/email/phone/links, producing the preview. The majority of the work and all of the risky autonomy.
  • Identity needed — Workday candidate home, LinkedIn Easy Apply, any resume-your-application flow, and the final submit. The user's browser, session, and hands.

Three reasons this fits Tayari specifically rather than merely imitating Anthropic: all the safety machinery already lives on the server path; the product invariant already says the human submits, and the extension is that surface; and origin_guard.py's rule — never enter credentials on an origin it did not start on — is meaningful on a clean profile and meaningless where credentials are already loaded as cookies.

Two tightenings while you're here
  • externally_connectable wildcards *.lovable.app and *.lovableproject.com — any page on that shared multi-tenant domain can message the extension. Narrow to the exact production origin.
  • all_frames: true runs content scripts inside third-party iframes embedded in Workday and LinkedIn pages. Scope to the top frame unless a specific ATS demands otherwise.

04 What not to adopt

PatternWhy not
LLM classifier as the permission boundary Anthropic's action space is open-ended — arbitrary shell, arbitrary files — so only a model can judge it. Tayari's is enumerable: navigate, click, fill, upload, submit, on known ATS domains. Deterministic rules are cheaper, faster, testable, and strictly more predictable. The guardrails already fail closed; don't dilute that with a probabilistic gate.
Dynamic workflows / a JS orchestration runtime Built to coordinate hundreds of subagents. Tayari's ceiling is nine named roles — and that orchestrator doesn't work yet: Subagent.execute prints a string and returns status: "completed". Fix or delete it before adding a layer above.
An agents control-plane daemon Solves multi-session lifecycle on a developer laptop. Celery + Redis and durable owner-bound leases already cover this. A second supervisor is duplication.
Plugin marketplaces and skill sync SHA pinning, Unicode collision handling, and a three-tier trust ladder exist because thousands of third parties author skills. Take progressive disclosure; leave the distribution machinery.
Pixel computer use Anthropic ships it and still ranks it last. Strictly dominated by the ref path on accuracy, token cost, determinism, and debuggability.
MCP statelessness as a rewrite MRTR and server/discover exist so servers can run serverless behind load balancers. Tayari's are stdio, single-tenant, low-QPS. The SDKs will deliver it. Only deterministic tools/list ordering is worth doing by hand, for prompt-cache hits.
Artifact-style runtime capabilities Anthropic's version is safe because claude.ai brokers every connector call against the viewer's account. Building an equivalent means becoming a credential broker. A static receipt page is the entire requirement.
A second browser-automation stack browser-use is pinned and load-bearing. The gap is in Tayari's addressing and guard layers, not the driver.

07 Confidence

Verified

Every path:line citation. Page.accessibility absent and Locator.aria_snapshot present on the installed Playwright 1.62.0, executed directly. The pin mismatch. autopilot_graph.py does not exist. agent.py:177–246 bypasses llm_service. _guard_credential_entry covers only input_text, per its own comment. LocalPlaywrightProvider emits no live_view_url. autofill_engine.js contains no model call. Subagent.execute returns hardcoded success. Three live ComputerUseDriver call sites.

Inferred

That page.accessibility.snapshot() still functions on 1.49.1 inside the Docker image — deprecated but present in that era; the image was not built and tested. That Workday and Greenhouse reflow enough to break [aria-label*=…] matching between renders — the standard failure mode for ATS single-page apps, but no live test was run against those portals. All effort sizes are estimates against the code as read, not measured.

Not investigated

codeact_repl.py, reflection_engine.py, agent_memory.py, the Go gateway's route surface for these paths, and src/lib/mcp/tools/ beyond the file listing. Any recommendation touching those needs sizing again first.
