What Anthropic shipped

A capability inventory across Cowork, Claude Code, the browser surfaces, the Agent SDK, MCP, Skills, and Artifacts — with the architectural idea behind each, and an explicit line between what is first-party confirmed and what is press-sourced.

01 Claude Cowork

An agentic surface for non-coding knowledge work — a third tab in the desktop app beside Chat and Code, plus web, mobile, and a Chrome side panel. Give it a goal and a scope; it plans, decomposes, runs code in a sandbox, coordinates parallel workstreams, and returns finished artifacts. Built on the same Agent SDK harness as Claude Code.

Execution moved off the machine, scope stayed on it

Work runs in an isolated environment on Anthropic's servers; the desktop app brokers access to the local folders you connected. Sessions continue with the app closed.

Decouple where the agent runs from what it can touch. Local access becomes a capability grant, not a colocation requirement — which is what buys cross-device continuity.

A permission dial with a real middle

Manual / Auto / Skip. Auto approves read-only tools automatically and runs a safety classifier before write or delete — and that check costs more usage.

Most products ship a binary. Pricing the safety check as a real compute line item is the honest version.

Dispatch: routing as conversation

One persistent thread decides whether a task is development work (spawns a Claude Code session) or knowledge work (stays in Cowork). App approvals inside Dispatch-spawned sessions expire after 30 minutes rather than lasting the session.

Approval scope shrinks with attention: unattended delegation gets a shorter trust window.

Constraints worth knowing

Memory does not carry from Chat into Cowork except within projects. Sessions can't be shared. Live artifacts and local MCP plugins are desktop-only. Web fetch and search run server-side and are not subject to configured network egress restrictions.

02 Claude Code

Dynamic workflows

Claude writes a JavaScript script that orchestrates subagents; a runtime executes it in the background. Primitives are agent() and pipeline(). Cap: 16 concurrent, 1000 agents per run.

Move the plan out of the context window and into code. Intermediate results live in script variables, so the model's context holds only the answer — and the orchestration becomes a diffable, rerunnable artifact.

Agent view — a control plane

claude agents groups background sessions by Needs input / Working / Completed. Backed by a per-user supervisor daemon with pre-warmed workers; sessions outlive the terminal and auto-move into git worktrees so parallel agents don't collide.

The supervisor restarts itself into new versions automatically.

Code review with a disproving agent

The managed service runs specialized agents in parallel, then a verification step checks candidates against actual code behavior to filter false positives. Findings rank by severity and post as a neutral check run that never blocks merges.

A separate agent whose only job is to disprove the others. Feedback reactions are collected after the PR merges — outcome-conditioned, not immediate.

Routines: stored prompt trusted, payload not

A fired trigger delivers the stored prompt as a trusted task, but the runtime text arrives wrapped in a block labelled untrusted data. A leaked bearer token yields data, not instructions.

When this over-triggered, they fixed the trust model rather than loosening it.

Auto mode becomes the default

From 14 Aug 2026, auto mode is the default permission mode for new sessions on Pro, Max, and Team. A separate classifier model reviews each action — and every inter-agent message — before it runs.

defaultMode: "auto" is ignored from repo-local settings, so a cloned repository cannot grant itself auto mode.

Remote control

Drive a locally running session from the web or mobile. Outbound HTTPS only — never opens an inbound port. Execution and filesystem stay local; the transcript is server-side, which is why zero-retention orgs cannot use it.

Multiple short-lived credentials, each scoped to one purpose and expiring independently.

03 The two browser surfaces

This is the split that matters most for anyone building an agent that touches the web. Anthropic shipped both an extension and an in-app pane, and the line between them is drawn on exactly one axis.

“The Browser pane uses a clean browser profile, separate from your personal browser, with none of your saved logins or history. Use it for building and testing your app and for sites that don't need your identity. When you want Claude to act as you in your logged-in sessions, use the Claude in Chrome extension instead, which shares your browser's login state.”
— Claude Code desktop docs

Browser pane — identity-free

Shipped 10 Jul 2026 press · desktop app

Tabbed Chromium inside the app. The agent reads pages as a YAML-style accessibility tree where every interactive element is tagged ref_N; the docs say plainly to prefer this over screenshots for verifying text and structure. The computer action accepts either a ref or a pixel coordinate — a hybrid with a documented preference order.

You drive it with your own mouse, sign in to sites yourself, and watch verification run in front of you. autoVerify is on by default: after every file edit Claude screenshots, checks for errors, and confirms the change works.

Refs are ephemeral — valid until the next DOM mutation. Write-action safety classifiers run in every permission mode here, not just Auto.

Claude in Chrome — identity-bearing

Pro / Max / Team / Enterprise · Chrome + Edge only

MV3 extension operating in your own logged-in profile. Multi-tab work, console and network reads, form fill, file upload, screenshots, GIF recording, scheduled browser tasks, 1Password with biometric approval. Connects to Claude Code over a native messaging host, not a network port.

API keys and long-lived tokens are refused — it requires a real account session.

Hard refusals no approval unlocks: purchases, account creation, CAPTCHA bypass. Pauses for you at login pages.

Anthropic's own position

Prompt injection remains “far from a solved problem.”

Mitigations are three layers: reinforcement learning against simulated malicious web content baked into the model; classifiers scanning untrusted content for adversarial commands in hidden text, manipulated images, and deceptive UI; and continuous red teaming. Plus per-site permissions — each subdomain separately — and admin allowlists.

04 Agent SDK & Managed Agents

Managed Agents has been in public beta since April 2026. Pricing is standard token rates plus $0.08 per session-hour of active runtime. Four resources: Agent, Environment, Session, Events.

Versioned agents, non-merging overrides

An Agent is a versioned, immutable-by-default config; version increments on any real change, and no-op updates create none. A Session can pass agent_with_overrides to replace model, system prompt, tools, MCP servers, or skills for that session only.

Three uniform rules: omit → inherit, null → clear, set → replace in full, never merge. The response returns a resolved snapshot while id/version still point at the base agent.

Staged rollouts and one-off experiments without config drift — and "replace, never merge" is what makes override behavior predictable at 3 a.m.

Budget as a first-class stop reason

max_list_cost takes a string of whole US cents, so no float rounding ever happens. The session pauses with stop reason budget_reached, enforced between model requests.

A ceiling that is checked at a defined boundary, not best-effort mid-flight.

Self-hosted sandboxes

Orchestration stays with Anthropic; tool execution moves to your infrastructure, so code, filesystem, and egress never leave your network.

Managed Agents is not zero-retention eligible — it is stateful by design.

05 MCP 2026-07-28

Released 28 July 2026 — final, not a candidate. The largest revision since launch, with all four Tier-1 SDKs updated simultaneously.

MCP Apps — the delegation argument

A tool declares a ui:// resource; the host renders it in a sandboxed iframe with no parent DOM, cookies, or navigation, bridged by JSON-RPC over postMessage. The app delegates actions to the host, which routes them through the user's already connected capabilities — so it can request an outcome like “schedule this meeting” without implementing a single provider integration.

06 Skills & Artifacts

Skills: progressive disclosure with a budget

A directory with a SKILL.md: frontmatter plus markdown. Only description and when_to_use sit in the always-loaded listing, and that text is truncated at 1,536 characters. The body loads on use — and then stays in context, so every line is a recurring cost.

Four precedence levels; context: fork runs a skill in its own subagent when even the loaded body is too much.

Skills: a trust ladder by location

Whether a skill's executable parts run depends on where the session lives, not who wrote it. Cloud session: full behavior. Cowork desktop: shell lines replaced with a placeholder. Any other local session: shell, attachments, and placeholders arrive as literal text.

Name collisions are compared Unicode-normalized, so look-alike characters can't shadow a real skill.

Artifacts: capability declared, identity resolved per viewer

A published page can call MCP connectors — but through the viewing account's own connections, not the publisher's. Two people opening the same dashboard see different data; the page never sees anyone's credentials. Actions with side effects also run under the viewer's account.

Which is exactly why a connector-backed artifact can never be shared to a public link on any plan.

Artifacts: the sandbox

Strict CSP blocks all external hosts. Everything inlined, images as data URIs, single page, 16 MiB ceiling, served from a sandboxed origin. Persistent storage is 20 MB per artifact, text-only, in personal or shared scope — and only works after publishing.

Governance most products skip: audit-log events, separate retention for private vs shared, and a compliance API for listing and deleting.

07 Patterns worth stealing

  1. Two surfaces, split by identity. Clean profile for agent work, identity-bearing for acting as the user. Same tools, different trust boundary — and it generalizes well beyond browsers.

  2. A classifier model as the permission boundary, not a rule engine — priced as real compute and said out loud.

  3. Structured page reads beat pixels. Accessibility tree with stable refs; screenshots explicitly deprioritized. Cheaper, more deterministic, mutation-scoped.

  4. Move the plan out of context and into code. Script variables hold intermediate results; the model's window holds only the answer.

  5. Stored prompt trusted, runtime payload untrusted. Directly transferable to any webhook-triggered agent.

  6. Progressive disclosure with a hard character budget. Description always in context, body on demand, fork when that's still too much.

  7. Versioned definitions with non-merging overrides that return a resolved snapshot and keep lineage intact.

  8. Statelessness via retry, not sockets. Return “I need input”; let the client retry with the answer.

  9. Capability declarations resolved against the viewer, with the publisher's declaration as the ceiling.

  10. Approval scope shrinks with attention. Attended sessions get session-length approvals; unattended ones get thirty minutes.
